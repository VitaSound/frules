## Карта этапов обучения модели

```text
[1] PRETRAIN          терабайты текста/кода  →  «язык + статистика мира»
         ↓
[2] SFT / INSTRUCT    пары prompt → answer   →  «слушай user, отвечай по задаче»
         ↓
[3] (опц.) RLHF/DPO   оценки людей/моделей  →  «полезно, безопасно, по формату»
         ↓
[4] ВАШ LoRA          jsonl Forth            →  «ещё чуть — Gforth, ваш стиль»
```

**Размер модели (0.5B, 7B)** задаётся на этапе **[1]** и **не растёт** на [2]–[4]: меняются только **значения** весов (+ маленький LoRA-адаптер).

## Таблица терминов

| Термин | По-простому | Что происходит технически | Для Forth / frules |
|--------|-------------|---------------------------|---------------------|
| **Параметр (parameter)** | «Ячейка памяти» сети | Одно обучаемое число в матрице | 0.5B = 500 млн таких чисел |
| **0.5B / 7B** | Размер / ёмкость модели | Число параметров; больше → больше паттернов | 0.5B — мало для алгоритмов на стеке |
| **Pretrain (претрейн)** | «Школа жизни» на интернете | Predict next token на огромном корпусе | Forth там ≈ 0%; зато Python, C, «код вообще» |
| **Token (токен)** | Кусок текста (~слово/часть) | Единица входа/выхода LLM | `: gcd` может быть 2–3 токена |
| **Transformer** | Архитектура LLM | Attention: каждый токен «смотрит» на предыдущие | Нет стека, нет VM — только текст |
| **SFT** | Supervised fine-tuning | Учебник: prompt → эталонный ответ | Ваш `train-merged.jsonl` |
| **Instruct / instruction-tuned** | Модель «ассистент» | SFT на диалогах «вопрос → ответ» | `Qwen2.5-Coder-0.5B-**Instruct**` |
| **LoRA** | Тонкая «накладка» | Мало новых весов; база заморожена (QLoRA: в 4-bit) | ~17 MB поверх 0.5B |
| **QLoRA** | LoRA + сжатая база | База в 4-bit, учится только adapter | Track A на RTX 4070 |
| **Loss (потери)** | Ошибка угадывания | Cross-entropy: насколько модель промахнулась по следующему токену | Низкий loss ≠ рабочий Forth |
| **Epoch (эпоха)** | Один проход по всему jsonl | Сколько раз модель видела каждую строку | 3 ep на 139 строк — мало для обобщения |
| **Overfit / зазубривание** | Запомнила train, не переносит | Отлично на тех же промптах, плохо на новых | Старый run: зазубрила **rules**, не gcd |
| **Generalization (обобщение)** | Перенос на новое | Работает на промптах/задачах вне train | 0.5B + Forth: practically нет |
| **Memorization** | Копирование train-пар | Ответ ≈ строка из jsonl | Даже этого 0.5B не сделала для gcd |
| **Curriculum** | От простого к сложному | Сначала `1 2 +`, потом `: square`, потом gcd | В frules не было; нужно для маленьких моделей |
| **Hold-out** | Задачи не из train | Только для проверки | `eval_holdout` в `tests/challenges/` |
| **System prompt** | Роль / правила в чате | Первое сообщение `role: system` | SFT: short (~50 tok); Ollama: full rules |
| **Reasoning (рассуждение)** | Цепочка шагов к ответу | Модель генерирует промежуточные шаги (CoT) | Forth-стек = нужен «scratchpad» или алгоритм |
| **CoT (chain-of-thought)** | «Думай вслух» в тексте | В ответе: стек, разбор, потом код | Помогает **большим** моделям; 0.5B ломается на длинной цепочке |
| **Rules (frules)** | Текст в промпте, не в весах | `.mdc` в SYSTEM; веса не меняются | Cursor / Ollama — сильнее LoRA 0.5B |
| **Merge LoRA** | Влить adapter в базу | Полные веса для Ollama/GGUF | Отдельно от качества Forth |
| **GGUF / Ollama** | Формат локального inference | Квантованная модель для чата | Rules в Modelfile ≠ train jsonl |

## Reasoning — что это такое

**Reasoning** в контексте LLM — не «логический процессор», а **способность выдать длинную цепочку текста**, которая *выглядит* как пошаговое решение и **ведёт к правильному финалу**.

Примеры:

| Без reasoning | С reasoning (CoT) |
|---------------|---------------------|
| «Ответ: `a b + c *`» | «Главная операция *; левое a b +; итог: a b + c *» → код |

Модель **не выполняет** шаги — она **предсказывает слова**, которые в train часто шли перед правильным ответом. Reasoning в больших моделях (7B+) усиливают:

- pretrain на коде и математике;
- SFT на задачах с разбором;
- иногда RLHF («награда за верный финал»).

**Forth** = reasoning про **стек** (что на TOS, что после `+`). Маленькой модели проще **галлюцинировать** `: word`, чем вести стек в голове. Отсюда идеи:

- CoT в jsonl («стек: …» → код);
- или **не** учить стек нейросетью, а **transpiler** (Lisp/WASM → Forth).

## «Изначально нейросеть просто распознаёт» — как появляется ответ на промпт

### После претрейна

Модель — **автодополнение**: «продолжи текст статистически правдоподобно».  
Промпт «напиши функцию» может продолжиться чем угodno — не обязательно ответом на вопрос.

### Instruction tuning (Instruct)

На миллионах пар:

```text
User:  Напиши hello world на Python
Assistant: print("hello world")
```

Модель учится: **после шаблона «User: … Assistant:»** генерировать **ответ на задачу**, а не случайное продолжение Wikipedia.

Технически это **тот же** next-token prediction, но на **другом** распределении данных.

### Chat template (Qwen)

```text
<|im_start|>system
…

<|im_start|>user
Implement gcd …

<|im_start|>assistant
```

Спец-токены говорят модели: «сейчас очередь **assistant** — это и есть ответ». Instruct-модель на этом и сидит.

### Ваш LoRA

Сдвигает статистику: «на Forth-промпт чаще `: … ;`, реже `def`».  
**Не** добавляет новый «режим мышления» — только смещает вероятности токенов.

## Чему можно научить 0.5B даже с $1M (применительно к Forth)

Миллион долларов **не увеличивает** 0.5B до 7B. Деньги покупают: GPU-время, **данные**, **инженеров**, ablation — но **потолок ёмкости** остаётся.

### Реалистично (даже с большим бюджетом на 0.5B)

| Цель | Достижимо? | Как |
|------|------------|-----|
| Формат `: word ( -- ) … ;` | **Да** | SFT + short system (у вас уже частично) |
| Короткие слова 1–2 строки (`mod 0=`, `dup +`) | **Частично** | 5k–50k синтетических пар, curriculum |
| Копия train на **идентичный** промпт | **Иногда** | Много повторов одной строки |
| Классификация «это число / оператор / скобки» → JSON | **Да** | Узкая задача, короткий вывод |
| «Перевод» фиксированного шаблона WASM→Forth | **Частично** | Если вывод короткий и однотипный |

### Нереалистично на 0.5B (даже за $1M)

| Цель | Почему |
|------|--------|
| 98 frules challenges hold-out | Нужны обобщение + алгоритмы + стек |
| Надёжный gcd / LRU / парсеры | Длинная логика, мало Forth в претрейне |
| Замена gforth + TESTS OK | Нет гарантии; модель не исполняет код |
| «Понимание» immediate / meta | Самомодификация парсера — вне статистики текста |
| Конкуренция Opus + frules rules | 100× меньше параметров |

### Куда имеет смысл потратить деньги **для Forth**, не упираясь в 0.5B

| Вложение | Эффект |
|----------|--------|
| **7B–14B** instruct + LoRA + curriculum | Шанс на часть challenges локально |
| **Rules** (Ollama/Cursor) без train | Сильный baseline без GPU train |
| **Transpiler** IR → Gforth | 100% на синтаксисе стека |
| **Генератор jsonl** (микро-примеры) | Дёшево, масштаб данных |
| Pretrain Forth-only с нуля | **Нет смысла** — мало данных, всё равно нужен general pretrain |

## Выводы Track A в терминах глоссария

1. **Pretrain** Qwen не давал Forth — LoRA должна была тащить парадигму с нуля на 0.5B → мало ёмкости.
2. **Bug full system + 1024 tok** — SFT учил не **assistant**, а обрезок **system** → ложный loss.
3. **Fix short system** — честный SFT; loss ~1.8; **memorization** gcd не случилась → потолок модели.
4. **Generalization** на hold-out для 0.5B **не ожидалась** — подтверждено.
5. **Reasoning** на стеке для железа → rules + большая модель или **transpiler**, не 0.5B LoRA.
