# 32B на Xeon 2008 года: когда RAM важнее VRAM (а Forth всё равно побеждает)

*Отдельная заметка из кроличьей норы [frules](https://github.com/VitaSound/frules) — Forth и ИИ. Видео: **TBD** — вставить URL YouTube перед публикацией.*

Я хотел локально запустить квантованные модели на **19–20 ГБ** — те, что не помещаются на ноутбуке с **16 ГБ** RAM, даже если есть GPU.

На ноутбуке (**RTX 4070**, Windows, **LM Studio**) загрузка весов **~32B Q4** не закончилась вежливым OOM. Система **зависла**.

Тогда я полез в противоположный угол кладовки с железом: **сервер 2008 года** — **2× Intel Xeon E5440**, **64 ГБ RAM**, **без GPU** — и **llama.cpp** в чисто CPU-режиме.

**Модель:** `deepseek-r1-distill-qwen-32b-q4_k_m.gguf`  
**Промпт:** написать факториал на Forth  
**Цель:** не скорость. Вопрос: *может ли старое железо с достаточным объёмом памяти запустить модель, которая по качеству недоступна на моём ноутбуке?*

## Две машины, один класс моделей

| | Ноутбук | Сервер |
|---|--------|--------|
| CPU | современный ноутбук | 2× Xeon E5440 |
| RAM | 16 ГБ | 64 ГБ |
| GPU | RTX 4070 | — |
| Стек | LM Studio (Windows) | llama.cpp (CPU) |
| Результат | зависание | грузится, работает |

Сервер ответил **да** на вопрос о размере. И ответил ещё и **~0.01 токена в секунду**.

Старт — около **23:56**. После **~1:20** реального времени в записи включил **ускоренную перемотку** — иначе смотреть высыхание краски до утра.

## Семь часов, два факториала, ноль TESTS OK

В **05:48** модель всё ещё не закончила цепочку рассуждений, но фрагмент, похожий на Forth, уже был. Скопировал **вариант 1**, запустил в **gforth** — **не сработало**: ошибка стека или синтаксиса; точный текст — в видео *(заполнить из [`FACTS.md`](FACTS.md))*.

Поток **ещё шёл**. Подождал.

В **06:51** появилась **вторая** попытка факториала. Запустил и её. **Снова fail.**

Тот же урок, который я снова и снова переучиваю в [frules](https://github.com/VitaSound/frules): большая instruct/reasoning-модель — не стековая машина Forth. Она генерирует текст слева направо. Postfix требует держать операцию в голове, пока кладёшь операнды. **Токены рассуждений код не исполняют.**

## Лебединая песнь, не бенчмарк

Такие эксперименты называют **лебединой песней** железа: что коробка 2008 года ещё может в эпоху LLM?

Для **вмещения** крупных Q4-моделей **64 ГБ системной RAM** на моём столе обыгрывают **16 ГБ + среднюю GPU**. Кандидаты того же класса: **Qwen2.5 32B Q4**, **QwQ 32B Q4**, **DeepSeek-R1 Distill Qwen 32B Q4** (этот прогон). Если бы выбирал одну демо-модель сегодня: **QwQ-32B Q4_K_M** — достаточно велика, чтобы показать преимущество RAM, и ещё не настолько огромна, чтобы сервер превратился в чистую печатную машинку.

Для **рабочего Forth** RAM не помогает. Нужен «завод»: алгоритм в удобной для модели IR, детерминированный transpile, **gforth** как судья. Это то, что я собираю вокруг Cursor — rules, skills и MCP — а не ещё один вечер копипасты из незаконченной chain-of-thought.

Платформа E5440 по современным меркам слабая — я бы не брал её и для PCIe GPU offload. Здесь **объём RAM** был единственным условием победы.

## Выводы

1. **VRAM — не единственный барьер.** Системная RAM важна, когда вся модель живёт в памяти хоста на CPU.
2. **Медленный inference — тоже inference.** 0.01 tok/s — шутка для чата; но на вопрос «запустится ли вообще?» — хватает.
3. **Не покупай стойку GPU, чтобы это выяснить.** У себя я уже записал правило: *железо покупаю после эксперимента, а не чтобы наконец начать* — та же линия, что при взгляде на б/у V100/NVLink.
4. **Fail format поучителен.** Два сломанных факториала за семь часов — урок дешевле, чем месяц Opus thinking loops.
